# 普通对话记忆

[English](../conversations.md)

## 自然语言控制

普通对话指没有 GitHub 仓库、也未登记为本地项目的聊天，默认不记忆。用户说
“请记住这个对话”或“关闭本对话记忆，保留笔记”，即授权对当前对话执行相应操作。
示例、引用和一般功能问答不构成开启授权。已登记的本地项目继续沿用项目记忆。

从 `CODEX_THREAD_ID` 或宿主对话元数据取得当前 ID，不得用标题或工作目录代替。
实际执行使用常规平台启动器；以下源码命令展示参数：

```bash
python ../../scripts/memoryctl.py conversation-enable --session-id <actual-session-id> --cwd /absolute/workspace
python ../../scripts/memoryctl.py conversation-disable --session-id <actual-session-id>
python ../../scripts/memoryctl.py conversation-list
```

开启命令返回笔记路径和即时上下文，应在当前对话立即使用，并披露新建笔记与索引。
关闭会保留笔记，停止加载和事实回写，已有文件名仍跟随标题；加 `--freeze-title` 可同时暂停改名。恢复相同 ID 后继续使用已有事实。
不要为了只给一个对话开启记忆而登记整个普通目录。

## 标题与文件名

笔记默认直接放在 `40-conversations/`，使用 `type: conversation` 和精确的
`conversation_id: codex:<session-id>`。文件名跟随界面显示标题，保留中文；文件系统
不允许的字符和保留名称会规范化，过长名称会缩短。同名或仅大小写不同的标题用稳定
ID 后缀区分，避免 Windows 文件冲突。不会为占用标题而覆盖已有文件，改名保留正文。

只读元数据适配器使用当前 Codex 环境 SQLite 中的 `threads.name`，或
`session_index.jsonl` 的标题记录。旧 `title` 字段可能是首条提示词，不作为标题来源。
不会读取聊天正文、认证信息或无关消息。元数据布局属于宿主实现细节；不可用时，从
宿主取得实际显示标题，在开启命令中传入 `--title`。标题暂不可用时，不清空或改名已有笔记。

## 自动同步改名

只有已登记笔记需要标题同步时，才运行脱离对话的本地同步进程，约每两秒检查这些
对话的标题。Windows 下无窗口运行，不安装计划任务，不联网，也不上传遥测。进程锁
阻止重复运行，Hook 也会同步当前标题。关闭整个集成或暂停所有笔记的标题同步后，同步进程退出。
关闭或归档聊天不会删除笔记。

```bash
python ../../scripts/memoryctl.py conversation-sync
```

该命令可重试本地标题同步。空闲期间改名产生的笔记与索引路径变化，会在下次可见
回写审查中披露。不要手动修改对话索引的受管理区块。

## 隔离与回写

已开启的对话只加载全局偏好和自己的笔记，不加载其他对话笔记、项目总览，也不伪造
分支页。它的 search/read 命令仅限自己的笔记。GitHub 与已有本地项目路由优先，
明确排除的仓库不能借此绕过范围限制。

保存持久目标、约束、已验证事实、决策和下一步，不复制聊天记录；未确认内容须明确
标注。首次开启和后续笔记变化都遵守与项目相同的逐文件可见审查及标记顺序。并发
对话只审核各自笔记和相应受管理索引的变更回执。

## 已有知识库与验证

按照[迁移说明](migration.md)把经验目录提升为根目录分区并添加对话索引，不要重新
初始化已有知识库。新知识库使用独立的 `10-memory`、`20-projects`、`30-reusable`
和 `40-conversations` 分区。

验证默认关闭的静默、即时开启、关闭恢复、同名标题、中文与保留名称、正文保留、
空闲时后台改名、元数据暂不可用、不同对话审查隔离，以及发布失败时的回滚。
