为已配置的 Obsidian 长期记忆知识库运行每周项目开工简报。

遵守知识库的 AGENTS.md，使用下方提供的已解析配置路径，包括自定义布局。读取记忆首页、全局记忆、项目总览、每个项目主页和分支页，以及理解工作所需的已链接项目子页。只有笔记中存在明确未完成目标、阻塞、下一步或近期持久进度时，才把项目视为活跃；不得把占位文字当作进度，也不得从仓库默认分支推断工作分支。

区分 GitHub 项目、明确登记的本地项目和各个分支。按精确的 github_repo 或本地 project_id 字段，以及区分大小写的 working_branch 匹配；不得用正文中的名字识别项目。遵守排除项和本地登记停用状态。注明带日期或历史证据与不确定状态，不得把它们写成已核实的当前进度。

选择历史资料时使用已配置的共享经验索引和相关经验；采用前核对适用条件、source_note、source_repo 或 source_project_id、source_branch 与 verified_on。普通对话笔记不是项目工作：不得读取其正文、用其排序任务、访问聊天数据库或会话记录，也不得开启对话记忆。

只更新已配置报告的 `updated` frontmatter 日期和“最新简报”部分，包含：

1. ISO 周和生成时间。
2. 五项有证据支持、价值最高的任务，包含项目链接、预期结果和优先理由。
3. 当前阻塞、受影响工作和具体解除动作。
4. 本周所需历史资料，并链接到精确决策、分支页或失败经验。

如果记录中的真实任务不足五项，不得虚构工作；把缺少位置标记为“优先级待确认”，并说明缺少什么信息。替换上期简报，不追加流水账，不得修改项目状态来迎合简报。

知识簇资料使用 Obsidian Wiki 内链，项目资料使用普通相对 Markdown 链接，避免报告产生额外图谱桥。结束前验证链接。使用已配置语言提供可见、逐文件的知识库回写审查，并遵守知识库的结束规则。永远不得保存凭据。
