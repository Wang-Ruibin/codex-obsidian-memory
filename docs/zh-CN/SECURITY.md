# 安全策略

[English](../../SECURITY.md)

## 报告安全漏洞

请使用 [GitHub 私密漏洞报告](https://github.com/Wang-Ruibin/codex-obsidian-memory/security/advisories/new)。项目处于早期开发阶段时，安全修复应用于 `main` 上的最新版本。

报告、Issue、Pull Request、测试夹具和日志中不得包含真实令牌、私钥、Cookie、私人知识库页面或其他凭据。

## 信任边界

- 本插件运行本地生命周期 Hook，并读取用户选择的 Markdown 知识库。信任前请在 `/hooks` 中审阅 Hook 定义。
- 显式准备运行环境时可以下载固定校验值的 uv 启动工具和私有 Python，不上传笔记、不安装 pip 包、不修改系统 PATH 或登记系统 Python。日常 Hook 不下载。设置完成后清理下载和解压临时文件，只保留仍在使用的私有解释器。
- 仓库身份来自只读 Git 命令。每个笔记都解析在配置的知识库内部，注入前遮蔽常见秘密模式。没有任何命令会删除或移动知识库。
- 本地项目使用明确登记的规范化根目录和固定 ID，未登记文件夹保持静默。登记不修改项目文件或 Git 设置；待审查记录只保存修改的笔记路径，即使登记前没有任务开始快照，也要求本轮可见披露。其他变化仍需常规快照。停用本地登记会保留笔记并停止参考检索。
- 提示开始时，插件只保存相对 Markdown 路径与 SHA-256 哈希的临时映射，不复制笔记正文。Stop 阶段要求可见审查逐一覆盖本轮范围内新建、修改或删除的文件，提供具体说明，再依次追加披露和审查标记。注释、代码块、引用、仅文件名或笼统的“已更新”不满足检查。不完整的审查在重试时仍会被拦截，并保留快照；成功结束后删除快照。
- 项目对话的审核覆盖本项目文件夹，以及本轮明确声明的共享笔记；其他项目的笔记变化不会列入。`claim-shared` 在本轮审核接受前独占全局记忆或共享经验文件，第二个对话需等待。知识库维护任务仍有意审核整个知识库。同一项目的同一笔记若被两个对话直接同时写入，仍需协调。
- 这是文件覆盖和最低说明要求的校验，不证明所述事实准确或详尽。依赖新记忆前请审阅笔记。缺少本轮标识或快照不可用时，无法检测文件变化；审查指令仍适用，但逐文件强制校验依赖提示开始时的快照。
- 分支路由和重复身份检查对完整 `working_branch` 值区分大小写，对 GitHub 仓库身份不区分大小写。在不区分文件名大小写的系统上，请使用不同的笔记文件名。
- Hook 上下文阈值为 16,000 token；过大的上下文可能只向 Codex 提供头尾预览，完整输出另行保存。
- 秘密遮蔽只是纵深防御，不是完整秘密扫描器。请勿在 Markdown 记忆文件中保存凭据。
