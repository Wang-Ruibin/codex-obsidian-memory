# 现有知识库接管验证

[English](../adoption-verification.md)

## 验证范围与结果

2026-09-21，在 Windows、Python 3.14.6 上，用源码中的 CLI 和 Hook 脚本验证了一个日常使用知识库的临时 Markdown 副本。这是实际既有知识库的接管练习，不是生成的模板样例，也不代表第三方安装成功。原知识库与全局 Codex 配置未改动。本文不发布私人笔记正文。

副本含 67 份 Markdown、28 个项目主页、28 个分支页和 66 个可见图谱节点。验证结果为必需笔记无缺失、身份无重复、链接无断链、无孤立节点。这些数量仅对应本次有日期的验证，不代表所有安装环境。[实际输出](../evidence/adoption-2026-09-21.json)只包含数量和检查结果。

| 检查 | 实际结果 |
|---|---|
| 不复制模板，接管现有自定义布局 | 所有原有 Markdown 哈希不变 |
| 查看配置并验证图谱 | 记忆已启用，验证通过 |
| 为真实本地 GitHub 项目加载上下文 | 包含对应项目主页 |
| 在临时副本写入一条偏好 | 缺少披露时被拦截 |
| 仅以笼统的“已更新记忆”重试 | 仍被拦截，变更证据保留 |
| 提供笔记路径和具体说明 | Stop 接受结束 |
| 向 Hook 提交新的会话标识 | 上下文中出现已保存的偏好 |
| 停用再启用集成 | 停用时 Hook 静默，启用后恢复上下文 |
| 卸载隔离的集成 | 副本和原知识库笔记均保留 |

Hook 子进程检查不能证明交互对话中的模型回忆，也不能确认新装客户端已经信任 Hook。用户反馈“做到 README 第三步后不知道怎么用”说明存在使用引导缺口，并不能证明其安装已成功。这条反馈促成了中英文 README 对输入位置、完成标志、适用范围检查和“保存—新对话—读取”练习的补充。

## 安全复现

在本仓库的克隆目录运行。提供一个既有知识库，以及其中已登记的本地 GitHub 项目。辅助脚本把可见 Markdown 复制到临时目录，使用隔离配置，结束后仅清理临时测试目录。它不会向日常客户端安装插件、修改全局设置，或删除、移动原知识库。输出只有数量和通过与否，不包含笔记正文。检查失败时，在本机通过 `validate` 检查知识库，不要把私人笔记上传到问题报告。

以下示例使用本次验证的自定义布局。请替换两个绝对路径，并按自己的布局调整每项映射。macOS/Linux 将 `py -3` 换成 `python3`，并使用本机路径。

```text
py -3 scripts/verify_adoption.py --source-vault C:/path/to/existing-vault --project C:/path/to/github-project --path home=00-知识库首页.md --path global_memory=10-知识库/长期记忆.md --path maintenance=10-知识库/知识库维护.md --path template=10-知识库/模板.md --path project_index=20-项目/项目总览.md --path projects_dir=20-项目 --path weekly_brief=10-知识库/每周开工简报.md --path monthly_audit=10-知识库/每月知识体检.md
```

退出码为 0 且 `checks` 下所有值均为 `true` 才算通过。脚本会校验原知识库和副本的哈希，不只依赖进程成功退出。正常设置流程见[迁移指南](../../plugins/codex-obsidian-memory/skills/codex-obsidian-memory/references/zh-CN/migration.md)。

## 接管与排障经验

- 现有布局用 `--no-template` 映射；知识库验证通过和当前仓库符合范围是两项独立检查。
- 在新会话中验证保存的事实，并指出来源笔记。仅说“记住了”不是持久化证据。
- Stop 再次要求审查时，补齐每个修改笔记的相对知识库路径和具体说明。不同项目文件夹里的同名笔记需要带目录路径。
- 在笔记里保留精确分支名。Windows 上为只在大小写上不同的分支使用不同笔记文件名。
- 报告故障时记录平台、输入布局、预期与实际结果。分享脱敏错误，不分享整个知识库。

## 发布判断

运行时修复以 0.4.1 打包。暂缓首个 **稳定 GitHub Release**：本次验证支持现有知识库接管和 Hook 行为，但未覆盖新用户 marketplace 安装、交互式 Hook 信任或独立用户确认。标为稳定版前，应至少记录一次全新客户端从安装、信任到新对话读取记忆的验收，并解决发现的问题。带版本的源码更新不代表这项更广泛的验收已经通过。
