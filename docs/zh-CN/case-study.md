# 案例：在 Obsidian 中构建确定性项目记忆

[English](../case-study.md)

本插件把一次始于 2026-08-21 的真实三天 Codex 会话进行通用化和脱敏包装。源知识库最初除 Obsidian 配置外为空，随后通过行为测试、用户纠错和图谱验证逐步形成完整系统。

## 构建过程

1. **保存持久信息，而不是对话流水账。**保留稳定偏好、上下文、决策、已验证结果、可复用失败经验和下一步；拒绝凭据与原始日志。
2. **使用 GitHub 作为项目身份。**早期清单把当前可见的 23 个公开仓库误认为账号总数，授权缺口由此形成“当前可见范围不能证明完整范围”的规则。
3. **本机规则留在项目记忆之外。**SSH、WSL 和沙箱行为属于用户级执行指引。
4. **用 Hook 替代被动文字指令。**一次盲测跳过了记忆加载，因此增加 `UserPromptSubmit`、压缩后 `SessionStart`、`SubagentStart` 和 `Stop` 四类确定性处理器。
5. **围绕仓库组织图谱。**一个 GitHub 仓库只拥有一个文件夹和一个项目主页；分支进度只属于精确 `working_branch` 页面。
6. **使用精确 frontmatter。**正文子串匹配会产生 `RAG` 与 `Agent-RAG` 等合理碰撞。
7. **按 origin 准入，而不仅按索引准入。**新的合格仓库即使尚未登记，也会获得全局记忆和模板。
8. **周期任务保持非破坏性。**周/月状态只在成功后推进；体检可以建议归档，但永远不执行归档。

## 源系统已验证快照

| 不变量 | 结果 |
|---|---:|
| 仓库文件夹 / 项目主页 | 25 / 25 |
| 精确分支页 | 26 |
| 可见图谱节点 | 60 |
| 生命周期处理器 | 4 |
| 断链 / 孤立节点 | 0 / 0 |
| 跨簇边 | 1 |

这些是案例结果，不是对其他用户知识库的承诺。每次安装都会独立验证。

## 可复用失败经验

| 失败 | 公开版设计响应 |
|---|---|
| 简单任务跳过建议性记忆指令 | 确定性生命周期 Hook |
| 把可见仓库数称为总数 | 不从当前授权覆盖推断总数 |
| 分支成为重复项目 | 一个仓库文件夹，分支使用独立页面 |
| 正文导致身份碰撞 | 精确 frontmatter 字段 |
| 仅索引准入漏掉新仓库 | GitHub origin 加显式排除表 |
| 旧 PowerShell 缺少 `Path.GetRelativePath` | 无依赖 Python 验证器 |

## 明确不打包的内容

private 仓库内容、凭据、本机特有执行规则、个人知识库页面和虚构周期结果均不进入公开包。公开项目只包含新模板、可配置路径、确定性脚本和可复用决策。
